# 车小记 · 微信小程序

按 `prototype.html` 实现的原生微信小程序，采用 JavaScript / WXML / WXSS，无第三方运行依赖。

## 运行

1. 在微信开发者工具中导入本目录 `F:\code\car-miniapp`，工具通过 `project.config.json` 使用 `miniprogram/`。
2. 配置文件暂用 `touristappid`。根据开发者工具的可用选项选择测试模式，或替换为你的小程序 AppID；真机预览、上传及发布需要你自己的有效 AppID 与权限。无需在代码中配置 AppSecret。
3. 编译后先进入「车辆」添加爱车。本版不自动注入示例数据。
4. 添加加油/充电记录，创建养护计划，在概览与统计页查看结果。

本地逻辑验证（需要支持 `node:test` 的 Node.js）：

```powershell
npm test
npm run check
```

无需执行 npm install 或构建 npm。

## 已实现

- 四个主页面：概览、账本、养护、车辆；四个子页面：记录、车辆表单、计划表单、统计。
- 燃油、HEV、插混/增程、纯电的多车档案，切换、编辑、归档与恢复；归档车辆的记录与计划只读，恢复后才能修改或删除。
- 加油、充电、保养、其他费用记录；新增、编辑、删除、历史补录与日期/里程校验；未关联计划的其他费用（停车、通行等）里程选填。
- 按车、月份、类型查看账本；月度费用分类与补能量；金额按整数分保存。
- 记录列表显示单价（¥/L、¥/kWh）和该条记录闭合区间的油耗或电耗；记账时填写金额和单价可自动算出油量或电量，手动改过的数量不会被覆盖。
- 其他费用可选类别：停车、通行、洗车、保险、年检、维修、罚款、其他；完成车险、年检计划时自动选好类别，统计页显示分类明细。
- 统计页：年度与累计已记支出、近 12 个月趋势、日均里程与年行驶估算、最近 5 个完整能耗区间、能源每公里成本；有多辆车时可切换「全部车辆合计」。
- 里程型计划按日均里程显示预计到达日期，标明为估算。
- 满箱法油耗；充电后 SOC 相同且用户逐段确认完整时计算充电侧区间电耗；算不出时，首页和统计页说明原因和下一步（如「已有一次加满，下次加满后即可算出油耗」）。
- 新记录沿用上次的「本次已加满」与「上次以来的充电都已记录」选择；充电表单只保留这一个完整性开关，并提示上次充电后电量。
- 疑似录错时先确认再保存：里程比上次多出 2000 km 以上且超过每天 800 km、加油超过 120 L / 充电超过 150 kWh、单价超出常见范围。
- 「更新里程」：在首页、养护页或里程过期提示上直接录入仪表读数，不需要记一笔费用。
- 自定义到期日期 / 里程；提前提醒；周期配置；完成计划同时记录保养或其他费用（如车险、年检）；按实际完成时间与里程顺延；按剩余天数/公里数占提前量的比例排序并显示剩余量；新建计划可套用常用项目模板（周期仅供参考，纯电车不含机油机滤）。
- 同步本地持久化，写入失败保留输入，不静默覆盖异常版本数据。
- 数据备份：在「车辆」页导出 JSON 备份并转发到聊天（如「文件传输助手」），从聊天文件恢复；恢复前按录入规则完整校验并确认，任何一项不通过都不写入。车库页显示上次备份日期；已有 10 条以上记录从未备份，或上次备份超过 30 天且之后有变化时，首页提醒备份（记录在单独的存储键 `car-miniapp:backup`）。

## 统计口径与边界

费用按发生日期统计。首页补能量是当月加油量/充入电量；统计页能耗来自**全部历史有效区间**，不随费用月份筛选。记录不完整时显示「—」，不使用估计数代替。

满箱区间排除起点当次油量，包含中间补油及终点油量。充电侧区间排除起点当次电量；要求起终 SOC 完全相同（采用保守规则）以及每段完整确认，结果可能包含充电损耗。区间在之后第一次回到相同状态（再次加满，或充电后 SOC 与起点相同）时闭合，中间其他 SOC 的充电电量计入该区间；与起点同里程的补能并入下一区间，不单独丢弃。

混动车的油耗和电耗分别按各自有效区间总里程计算，不能相加，也不代表纯油/纯电模式能耗。

能源成本 = 完整区间内的补能花费 ÷ 区间里程，与油耗/电耗用同一批区间，不包含保养、保险等费用，因此不是总用车成本；未计算无可靠依据的总每公里成本。年度、累计和近 12 个月趋势都按记录日期统计「已记支出」。「全部车辆合计」只合计支出，能耗与里程仍按单车计算。

日均里程用最新读数与「至少 90 天前的最后一个读数」（历史不足 90 天时用最早读数）计算，跨度不足 14 天不估算。里程型计划的预计到达日期从最新读数的日期起按日均推算；若推算日期已过，提示可能已到达并建议更新里程。

同一天内按累计里程排序；暂不记录精确时分。一次手动里程读数在车辆档案中保存，后续当前里程由此读数与记录共同推导。新记录不预填里程，输入框只提示最近读数，避免沿用旧读数把能耗算错。里程超过 30 天未更新时，养护计划会提示核对。「更新里程」把当天的仪表读数保存为车辆档案中的手动读数，不能小于已有记录的里程。

删除/修改完成记录会重新推算关联计划；重复计划采用最近完成记录。更改计划周期会重算下次到期。首次到期条件只在没有完成记录时使用。计划删除保留已发生的费用记录。

## 数据和上线范围

这是**本地可用版本**。数据位于微信本地存储 `car-miniapp:v1`，没有服务器、跨设备同步或云端备份，清理缓存/卸载/换设备可能丢失数据。应用不调用网络，也不收集车牌、定位、手机号或票据。

备份需要用户手动导出：「车辆」页用 `wx.shareFileMessage`（基础库 2.16.1+，只能在点击时调用）把 JSON 文件转发到聊天，恢复时用 `wx.chooseMessageFile`（2.5.0+）选择该文件。恢复会整体替换本机数据；本机数据损坏或格式不兼容时也能恢复。备份文件包含全部车辆与费用记录，请妥善保管。`wx.chooseMessageFile` 属于隐私接口（「收集你选中的文件」），上线前需在小程序管理后台的用户隐私保护指引中声明，否则恢复会失败。具体声明与授权方式以微信官方规则为准。

存储结构带版本号。读取和恢复时先经过 `store.js` 中的 `migrate()`：来自更新版本的数据会提示先更新小程序，不会被覆盖；以后修改结构时，在这里逐版本升级。

养护为站内提醒，没有后台定时推送；尚未接入微信订阅消息。上线需要配置真实 AppID、按实际业务完善隐私说明，并在微信开发者工具与真机验收。如需云同步，应在服务端实现身份与车辆所有权校验后接入，不应直接信任客户端 vehicleId。

## 目录

```text
miniprogram/
  app.*                  全局配置与样式
  pages/                 8 个原生页面
  templates/shared.wxml  车辆选择、记录列表与提醒卡片
  utils/domain.js        校验、统计、能耗与计划推算
  utils/store.js         本地事务式读改写、版本迁移、备份校验与恢复
  utils/backup.js        备份文件的写入、读取与恢复确认文案
  utils/ui.js            页面共享逻辑
tests/                   业务边界与存储测试
scripts/check.js         语法、配置、页面路由检查
DESIGN.md                完整产品设计
prototype.html           原交互原型（独立示例数据）
```

## 微信端人工验收

- 四个 Tab 切换与返回；分别新建四种能源车，验证入口和数据隔离。
- 建车 → 加油/充电 → 账本编辑 → 删除；关闭重开后确认数据保存。
- 连续两次加满并夹一次未加满，核对油耗；漏记后检查该区间不计入。
- 充电缺少 SOC/完整确认时无电耗；相同边界与完整记录时有结果。
- 新建日期和里程双条件计划，检查任一到期；完成、修改完成记录、删除完成记录后核对顺延。
- 归档与恢复；月份切换；空状态；金额格式错误；历史里程冲突。
- 导出备份并发送到「文件传输助手」；清除数据或换机后从聊天文件恢复，核对车辆、记录与计划；选择其他文件时有提示且数据不变；隐私指引未声明时的失败提示。
- 新车首次加油、只有一次加满、标记漏记、充电缺电量时，首页与统计页的原因提示；连续两次记账时「本次已加满」是否沿用。
- 输入明显异常的里程或单价时弹出确认；「更新里程」弹窗输入（`wx.showModal` 的输入框需要基础库 2.17.1+）；套用计划模板后车险、年检需要选择日期。
- 记录列表的单价与区间油耗行；金额 + 单价自动算出油量；其他费用类别选择。统计页的趋势条形、年度与累计卡片、里程卡片在小屏上的排版；多车时「全部车辆合计」切换。
- iOS/Android 真机键盘、日期选择、字体尺寸、底部安全区。

自动检查不能替代微信 WXML 编译与真机验收。
