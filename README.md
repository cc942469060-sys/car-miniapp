# 车小记 · 微信小程序

按 `prototype.html` 实现的原生微信小程序，采用 JavaScript / WXML / WXSS，无第三方运行依赖。

## 运行

1. 在微信开发者工具中导入本目录 `F:\code\car-miniapp`，工具通过 `project.config.json` 使用 `miniprogram/`。
2. 配置文件暂用 `touristappid`。根据开发者工具的可用选项选择测试模式，或替换为你的小程序 AppID；真机预览、上传及发布需要你自己的有效 AppID 与权限。无需在代码中配置 AppSecret。
3. 编译后先进入「车辆」添加爱车。本版不自动注入示例数据。
4. 添加加油/充电记录，创建养护计划，在概览与统计页查看结果。

本地逻辑验证（需要支持 `node:test` 的 Node.js）：

```powershell
npm test
npm run check
```

无需执行 npm install 或构建 npm。

## 已实现

- 四个主页面：概览、账本、养护、车辆；四个子页面：记录、车辆表单、计划表单、统计。
- 燃油、HEV、插混/增程、纯电的多车档案，切换、编辑、归档与恢复。
- 加油、充电、保养、其他费用记录；新增、编辑、删除、历史补录与日期/里程校验。
- 按车、月份、类型查看账本；月度费用分类与补能量；金额按整数分保存。
- 满箱法油耗；充电后 SOC 相同且用户逐段确认完整时计算充电侧区间电耗。
- 自定义到期日期 / 里程；提前提醒；周期配置；完成计划同时记录费用；按实际完成时间与里程顺延。
- 同步本地持久化，写入失败保留输入，不静默覆盖异常版本数据。

## 统计口径与边界

费用按发生日期统计。首页补能量是当月加油量/充入电量；统计页能耗来自**全部历史有效区间**，不随费用月份筛选。记录不完整时显示「—」，不使用估计数代替。

满箱区间排除起点当次油量，包含中间补油及终点油量。充电侧区间排除起点当次电量；要求起终 SOC 完全相同（采用保守规则）以及每段完整确认，结果可能包含充电损耗。

混动车的油耗和电耗分别按各自有效区间总里程计算，不能相加，也不代表纯油/纯电模式能耗。未计算无可靠依据的每公里成本。

同一天内按累计里程排序；暂不记录精确时分。一次手动里程读数在车辆档案中保存，后续当前里程由此读数与记录共同推导。里程超过 30 天未更新时，养护计划会提示核对。

删除/修改完成记录会重新推算关联计划；重复计划采用最近完成记录。更改计划周期会重算下次到期。首次到期条件只在没有完成记录时使用。计划删除保留已发生的费用记录。

## 数据和上线范围

这是**本地可用版本**。数据位于微信本地存储 `car-miniapp:v1`，没有服务器、跨设备同步或云端备份，清理缓存/卸载/换设备可能丢失数据。尚未提供文件导入导出。应用不调用网络，也不收集车牌、定位、手机号或票据。

养护为站内提醒，没有后台定时推送；尚未接入微信订阅消息。上线需要配置真实 AppID、按实际业务完善隐私说明，并在微信开发者工具与真机验收。如需云同步，应在服务端实现身份与车辆所有权校验后接入，不应直接信任客户端 vehicleId。

## 微信端人工验收

- 四个 Tab 切换与返回；分别新建四种能源车，验证入口和数据隔离。
- 建车 → 加油/充电 → 账本编辑 → 删除；关闭重开后确认数据保存。
- 连续两次加满并夹一次未加满，核对油耗；漏记后检查该区间不计入。
- 充电缺少 SOC/完整确认时无电耗；相同边界与完整记录时有结果。
- 新建日期和里程双条件计划，检查任一到期；完成、修改完成记录、删除完成记录后核对顺延。
- 归档与恢复；月份切换；空状态；金额格式错误；历史里程冲突。
- iOS/Android 真机键盘、日期选择、字体尺寸、底部安全区。

自动检查不能替代微信 WXML 编译与真机验收。
